Bulk Merge for GitHub

Bulk merge ready pull requests from GitHub's pull request list.

GitHub token

Unlocked until Chrome closes. On disk the token is kept only encrypted with your passphrase.

Unlocks until Chrome closes. Forgot it? and save a new one.

Create a classic token with the repo scope. For an organization with SAML SSO, authorize the token for that organization afterwards.

The token is encrypted with your passphrase (at least 10 characters) before it is saved, and you unlock it once each time Chrome starts. The passphrase is never stored; if you lose it, save the token again.

Fine-grained tokens are refused: GitHub does not guarantee they can read check runs, and checks it cannot read could look green.

When a pull request is merged

  1. Open, not a draft, no merge conflicts

    GitHub must also report it clean to merge, so branch rules and required reviews are respected.

  2. Every check finished and passed

    On the head commit, every check run and status is complete with success, neutral or skipped. Running, cancelled, failed, unreadable, or no checks at all means not ready.

  3. Checked again right before it merges

    Each pull request is re-read just before its merge and merged only at the commit you confirmed, without bypassing repository rules.

  4. A mixed selection is confirmed twice

    Any pull request can be ticked. If the selection includes some that are not ready, Bulk merge says how many will be skipped and asks again before merging the ready ones.
